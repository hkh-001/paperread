## 0. 先给结论：这篇论文要解决什么

这篇论文不是提出一个新的 Agent 算法，而是尝试回答三个全局问题：

1. **一个基于大语言模型的自主智能体由什么组成？**
2. **这些智能体能被用到哪些领域？**
3. **怎样判断一个智能体是否真的有效？**

作者给出的主线是：

```text
Agent Construction
├── Architecture Design
│   ├── Profile
│   ├── Memory
│   ├── Planning
│   └── Action
└── Capability Acquisition
    ├── Fine-tuning
    └── Without Fine-tuning
        ├── Prompt Engineering
        └── Mechanism Engineering

Agent Application
├── Social Science
├── Natural Science
└── Engineering

Agent Evaluation
├── Subjective Evaluation
└── Objective Evaluation
```

最值得记住的不是论文列举了多少系统，而是它提供了一个拆解 Agent 的坐标系：

> **Profile 决定“我是谁”，Memory 保存“我经历了什么”，Planning 决定“接下来怎样做”，Action 把决策变成对环境有影响的行为。**

这四个模块不是四个互不相干的插件。Profile 会影响什么值得记忆、什么计划符合角色；Memory 和 Planning 会共同影响 Action；Action 又改变环境和内部状态，产生新的观察，进入下一轮循环。

## 1. 论文基本信息与定位

### 1.1 论文类型

这是一篇 **Survey / Review Article**，核心贡献是：

- 整理领域，而非提出单个新模型；
- 提出统一分类框架；
- 将早期分散的 LLM Agent 工作放入同一坐标系比较；
- 归纳应用、评价方法和开放挑战。

所以阅读时不应问“模型精度提高多少”，而应问：

- 分类维度是否合理？
- 是否覆盖了决定 Agent 能力的关键部分？
- 不同分类之间是否互斥？
- 作者总结的挑战是否仍成立？
- 哪些内容因论文主要覆盖 2021–2023 年工作而已经过时？

### 1.2 一句话概括

作者把 LLM-based Autonomous Agent 研究组织成“**构建—应用—评价**”三部分，并用 Profile、Memory、Planning、Action 四模块统一描述智能体架构。

### 1.3 为什么适合作为第一篇

实验室大纲包含情感智能体、拟人智能体、个性化推荐、知识增强、多轮协作决策、记忆、规划、工具使用、强化学习和心理测量。直接进入某篇具体论文，会看到大量局部技术但不知道它处在什么位置。这篇综述先提供“地图”：以后读具体论文时，可以先判断它主要改了哪个模块、采用何种能力获取方式、在哪个场景评测，以及指标是否覆盖真正目标。

## 2. 从普通 LLM 到 Agent：根本差异是什么

### 2.1 直觉

普通 LLM 最典型的交互是：

```text
输入文本 → 生成文本
```

Agent 的典型交互是：

```text
目标
  ↓
感知当前环境/读取历史
  ↓
形成或修正计划
  ↓
选择动作/调用工具
  ↓
环境发生变化并返回反馈
  ↓
更新记忆和计划，继续循环
```

区别不在于 Agent “说得更像人”，而在于它处于一个**跨时间的闭环**中：当前行为会改变未来看到的环境，过去的经验会影响未来决策。

### 2.2 正式定义中的关键成分

论文引用 Franklin 与 Graesser 对 autonomous agent 的定义。拆开后包含：

- **Situated**：Agent 位于某个环境中，而不是悬空回答问题；
- **Senses**：它能获得环境信息；
- **Acts**：它能对环境采取行动；
- **Over time**：存在持续过程，而非一次性输出；
- **Own agenda**：有目标或优化方向；
- **Affect future sensing**：当前行动会改变之后获得的观察。

因此，并非“给 LLM 加一段角色提示词”就自动成为自主智能体。至少要检查它是否有状态、目标、动作和反馈循环。

### 2.3 LLM 在 Agent 中扮演什么角色

LLM 通常是控制器或推理核心，它提供：

- 自然语言理解与生成；
- 常识和世界知识；
- 任务分解与计划生成；
- 工具选择和参数生成；
- 对观察、失败和反馈的解释。

但 LLM 并不天然等于完整 Agent。长期状态、可靠执行、外部工具、权限、安全约束和可验证反馈往往需要额外模块。

### 2.4 与传统强化学习 Agent 的比较

论文强调，传统 Agent 往往在较封闭环境中针对固定任务训练；LLM Agent 借助预训练知识和自然语言接口，在零样本或少样本条件下可以处理更多开放任务。

这不代表 LLM Agent 一定优于 RL Agent：

| 维度    | 传统 RL Agent   | LLM Agent             |
| ----- | ------------- | --------------------- |
| 先验知识  | 通常较少，依靠环境交互学习 | 预训练中拥有大量语言与世界知识       |
| 状态/动作 | 往往明确定义、结构化    | 常以自然语言表示，更灵活但更不稳定     |
| 学习信号  | 奖励和轨迹         | Prompt、示例、反馈、工具结果、奖励等 |
| 可解释接口 | 不一定自然         | 可输出自然语言计划与理由          |
| 可靠性   | 在固定环境可较稳定     | 容易幻觉、提示敏感、长程误差累积      |
| 泛化    | 常受训练环境约束      | 表面泛化较强，但真实稳健性需验证      |

## 3. 论文的两层构建框架

作者把 Agent Construction 分为两个问题：

### 3.1 Architecture Design：架构设计

相当于决定系统有哪些模块、模块怎样交互。论文类比为传统神经网络的“网络结构”。统一架构包含：

1. Profile
2. Memory
3. Planning
4. Action

### 3.2 Capability Acquisition：能力获取

相当于让既定架构真正具备完成任务所需的知识、技能和经验。论文类比为传统机器学习中的“参数学习”，但 Agent 时代不止参数学习：

- Fine-tuning：改变模型参数；
- Prompt Engineering：在上下文中提供规则、例子和信息；
- Mechanism Engineering：设计试错、协作、经验积累、自我演化等机制。

这个区分非常重要。很多论文的“新方法”并未改变底层 LLM，而是改变外部工作机制。评价时要问：提升来自更强模型、更多上下文、更好工具，还是更合理的机制？

## 4. Profile Module：Agent 是谁

### 4.1 Profile 解决的问题

Profile 规定 Agent 扮演的角色、拥有的属性、职责和行为倾向。例如：教师、程序员、心理支持者、电影爱好者、内向或外向角色。

论文列出三类信息：

- **人口统计信息**：年龄、性别、职业等；
- **人格/心理信息**：人格特质、价值倾向、心理状态；
- **社会信息**：与其他 Agent 的关系、身份与责任。

不同任务需要不同 Profile。做软件开发时，职责分工可能比年龄重要；做人类行为模拟时，人口和心理特征可能更关键。

### 4.2 三种 Profile 生成方法

#### 4.2.1 Handcrafting：人工设定

例子：在系统提示中写“你是一名外向、善于鼓励他人的教师”。

优点：

- 可控；
- 目标明确；
- 适合少量角色。

缺点：

- 大规模构建成本高；
- 设计者的刻板印象会进入角色；
- 一句人格描述未必能稳定控制长期行为。

#### 4.2.2 LLM Generation：由 LLM 生成

先给生成规则和少量种子角色，再让 LLM 扩展更多 Profile。

优点是快速和规模化；缺点是精确控制不足，可能生成相互矛盾或分布失真的角色。

#### 4.2.3 Dataset Alignment：与真实数据对齐

将真实人群数据中的属性转换成自然语言 Profile。它比纯虚构更接近现实分布，但仍存在：

- 数据代表性问题；
- 敏感属性和隐私问题；
- 将统计群体特征硬套到个体的风险；
- 数据中的历史偏见被模型复现。

### 4.3 与实验室方向的关系

- **拟人智能体**：角色、人格、主体性的构建和测量；
- **个性化推荐**：用户 Profile 不能只记录静态偏好，还要表示不确定性与变化；
- **情感智能体**：支持者角色既要有共情倾向，也要遵守边界和安全规范；
- **人机关系研究**：Profile 会影响用户对 Agent 的信任、依赖和关系判断。

### 4.4 必须保持的批判

Profile 并不等于真实人格。Prompt 中写“外向”只能说明系统被施加了一个控制条件，不能据此证明模型拥有稳定人格。要证明“人格”，至少需要跨情境一致性、时间稳定性、量表效度、行为证据和对提示扰动的稳健性。

## 5. Memory Module：Agent 怎样利用过去

这是和实验室方向联系最紧密的模块之一。

### 5.1 Memory 为什么必要

如果 Agent 每轮都只看到当前输入，它无法：

- 记住用户偏好和个人事实；
- 保持角色与承诺一致；
- 从成功或失败中积累经验；
- 追踪长期目标和状态变化；
- 理解人机关系如何随交互演化。

Memory 的核心不是“存得多”，而是：

```text
该写入什么 → 如何表示 → 何时取回 → 怎样更新/合并/遗忘 → 如何验证被正确使用
```

### 5.2 Memory Structure：统一记忆与混合记忆

#### 5.2.1 Unified Memory

论文所谓 unified memory 主要指只模拟短期记忆：信息直接放入当前上下文，通过 in-context learning 使用。

优点：实现简单，近期信息完整。缺点：

- 上下文窗口有限；
- 成本随历史增长；
- 大量无关历史产生干扰；
- 很难显式更新、删除和处理冲突。

#### 5.2.2 Hybrid Memory

显式结合：

- **短期记忆**：当前任务、最近对话、当前观察；
- **长期记忆**：过去事件、总结、技能、用户偏好和经验。

典型过程：将长期内容存到外部存储，需要时检索少量相关条目放回当前上下文。

这解释了为什么“Conversation History ≠ 完整的 Memory System”。完整历史只是潜在记忆源，没有自动解决选择、更新、冲突、遗忘、时间有效性和隐私。

### 5.3 Memory Format：记忆用什么形式保存

#### 5.3.1 Natural Language

直接保存事件或总结文本。

- 优点：丰富、可读、容易交给 LLM；
- 缺点：冗余、歧义、检索不稳定、结构化修改困难。

#### 5.3.2 Embedding

把记忆编码为向量，用相似度检索。

- 优点：语义检索效率高；
- 缺点：相似不等于真正相关；时间、否定、因果和数值差异可能表达不佳；向量本身不可读。

实际系统常用 key-value：向量作检索键，原始文本作值。

#### 5.3.3 Database

用数据库和 SQL 等结构化操作管理记忆。

- 优点：精确增删改查、可审计；
- 缺点：先要把自然语言可靠地映射成 schema 和操作，schema 本身可能限制信息。

#### 5.3.4 Structured List / Graph

用列表、三元组、树或图表达人物、事件和关系。

- 优点：关系清楚，便于推理、更新和路径追踪；
- 缺点：结构抽取可能丢失语境，错误关系会影响后续推理。

### 5.4 Memory Operation：读、写、反思

#### 5.4.1 Memory Reading

从全部记忆中找出当前任务最值得使用的部分。论文总结了三个信号：

- Recency：是否最近；
- Relevance：与当前问题是否相关；
- Importance：内容本身是否重要。

#### 5.4.2 Memory Writing

决定新观察是否写入以及怎样写入。两个关键问题：

1. **Memory duplication**：相似记录不断重复怎么办？
2. **Memory overflow**：容量满了，删除或压缩什么？

简单 FIFO 会删最旧内容，但“旧”不代表“不重要”。对长期人机关系而言，早期承诺可能比昨天的闲聊更重要。

#### 5.4.3 Memory Reflection

把低层经历总结成更高层知识。例如从“多次在研究任务中查资料、联系图书管理员、讨论论文”，抽象出“这个角色非常投入研究”。

Reflection 的价值：压缩、归纳、形成可迁移经验。风险：

- 抽象可能误判；
- 错误总结会反过来影响大量未来决策；
- 多层总结后难以追溯原始证据；
- 模型可能把临时状态固化为稳定人格。

## 6. 论文唯一核心公式：记忆检索评分

论文式（1）：

$$
m^* = \arg\max_{m \in \mathcal{M}}
\left(
\alpha s_{rec}(q,m)
+ \beta s_{rel}(q,m)
+ \gamma s_{imp}(m)
\right)
$$

### 6.1 每个符号是什么意思

- $\mathcal{M}$：全部候选记忆集合；
- $m$：其中一条候选记忆；
- $q$：当前查询，可以是用户问题、任务目标或当前环境状态；
- $s_{rec}(q,m)$：recency，记忆的新近程度；论文写成与 $q$ 相关的统一形式，实践中常主要依赖时间差；
- $s_{rel}(q,m)$：relevance，记忆与当前查询的相关度；
- $s_{imp}(m)$：importance，记忆自身的重要性，与当前查询可以无关；
- $\alpha,\beta,\gamma$：三个信号的权重；
- $\arg\max$：不是求最高分本身，而是找到让总分最高的那条记忆 $m^*$。

### 6.2 直觉

人回忆事情时，不会只依据“最像当前问题”。我们也容易想起：

- 刚刚发生的事；
- 与眼前问题高度相关的事；
- 对自己非常重要的事。

公式把这三种因素线性加权。

### 6.3 一个数值例子

用户问：“我上次说过不能吃什么？”系统有三条记忆：

| 记忆 | Recency | Relevance | Importance |
|---|---:|---:|---:|
| A：昨天喜欢看科幻片 | 0.9 | 0.1 | 0.2 |
| B：三个月前说花生严重过敏 | 0.2 | 0.9 | 1.0 |
| C：一周前不喜欢香菜 | 0.6 | 0.8 | 0.4 |

若 $\alpha=0.2,\beta=0.4,\gamma=0.4$：

$$
Score(A)=0.2\times0.9+0.4\times0.1+0.4\times0.2=0.30
$$

$$
Score(B)=0.2\times0.2+0.4\times0.9+0.4\times1.0=0.80
$$

$$
Score(C)=0.2\times0.6+0.4\times0.8+0.4\times0.4=0.60
$$

于是检索 B。虽然 B 最旧，但相关性和安全重要性更高。

### 6.4 三个分数可以怎样实现

论文没有规定唯一实现。常见方式包括：

- Recency：指数衰减 $e^{-\lambda \Delta t}$，时间越久分数越低；
- Relevance：查询和记忆 embedding 的 cosine similarity；
- Importance：规则、人工标签、小模型分类或让 LLM 打分。

例如余弦相似度：

$$
\cos(\mathbf{q},\mathbf{m})=
\frac{\mathbf{q}\cdot\mathbf{m}}
{\|\mathbf{q}\|\|\mathbf{m}\|}
$$

它比较两个向量方向是否接近。接近 1 表示语义表示方向相似，但不保证事实支持关系成立。

### 6.5 为什么要归一化

如果 recency 在 $[0,1]$，relevance 在 $[-1,1]$，importance 在 $[1,10]$，即使权重相同，importance 也会天然支配总分。因此实际使用前应把各分数变到可比较范围，或通过验证集学习权重。

### 6.6 公式的隐含假设

1. 三个因素可以被可靠量化；
2. 三者的作用可用线性加和表示；
3. 一条最高分记忆足以支持任务，或 top-k 是简单扩展；
4. 各条记忆相互独立评分；
5. 重要性是静态属性；
6. 相关性可由向量距离等近似。

这些假设在复杂任务中可能失效。例如多跳问题需要同时组合两条各自看似不够相关的记忆；偏好漂移要求理解“旧信息已被新信息覆盖”，而不是简单叠加。

### 6.7 这个公式不能解决什么

- 两条记忆相互矛盾时信谁；
- 事实是否过期；
- 当前用户是否允许系统继续保存某信息；
- 检索出的记忆是否被生成模型正确使用；
- 多条记忆如何组合进行时间或因果推理；
- 高分记忆是否是错误总结或幻觉。

因此，Memory Evaluation 至少应拆成：

```text
写入正确性 → 存储/更新正确性 → 检索召回 → 证据排序 → 阅读/推理 → 最终回答
```

## 7. Planning Module：Agent 怎样决定未来行动

### 7.1 Planning 为什么必要

复杂任务往往不能用一个动作完成。Planning 负责把目标拆成子目标，安排顺序，并在条件变化时调整。

作者用一个关键维度分类：**规划过程中是否使用反馈**。

### 7.2 Planning without Feedback

先产生计划，再执行；执行过程中的观察不反向改变后续计划，或反馈作用很弱。

#### 7.2.1 Single-path Reasoning

每一步只有一个后继步骤，形成一条链：

```text
Step 1 → Step 2 → Step 3 → Answer/Action
```

代表思想包括 CoT、Zero-shot CoT、任务分解。优点是成本较低、过程直观；缺点是一旦早期步骤错误，后面会沿错误路径继续。

#### 7.2.2 Multi-path Reasoning

同时保留多个候选思路，再搜索或选择：

```text
             → Plan A → ...
Current state → Plan B → ... → choose
             → Plan C → ...
```

代表包括 Self-consistency、Tree of Thoughts、Graph of Thoughts、MCTS 式规划。

优点：有机会绕过局部错误；缺点：

- 调用成本高；
- 候选都来自同一模型，错误可能高度相关；
- 如果评价器也不可靠，多路径只是在更多错误中做选择。

#### 7.2.3 External Planner

LLM 负责把自然语言任务转换成形式化描述，例如 PDDL；成熟规划器负责搜索；LLM 再把结果翻回自然语言。

它体现“语言模型做擅长的语义转换，符号规划器做擅长的约束搜索”。关键风险是接口转换：若 LLM 漏掉前置条件，后续规划器再正确也无济于事。

### 7.3 Planning with Feedback

为什么需要反馈：

- 初始计划很难预见全部条件；
- 动作执行结果具有不确定性；
- 环境会变化；
- 长链条中小错误会累积。

论文分三类反馈：

#### 7.3.1 Environment Feedback

来自外部世界的观察、成功/失败、报错、状态变化。ReAct 的 Thought–Action–Observation 就是典型闭环。

#### 7.3.2 Human Feedback

人纠正目标、偏好或环境描述。它能补充系统看不到的信息，也能帮助价值对齐，但成本高、反馈可能不一致。

#### 7.3.3 Model Feedback

模型检查或批评自己的输出，如 Self-Refine、SelfCheck、Reflexion。

关键批判：**模型生成了批评，不代表批评正确。** 同一模型可能重复原有偏见，也可能给错误答案编出合理解释。必须通过外部可验证结果或独立评价验证反思是否有效。

### 7.4 Planning、Reasoning、Reflection 的区别

| 概念 | 核心问题 | 典型产物 |
|---|---|---|
| Reasoning | 从信息怎样推到结论 | 中间推理、判断 |
| Planning | 为达成未来目标采取哪些步骤 | 子目标、动作序列 |
| Reflection | 根据过去结果总结并修正什么 | 反馈、经验、规则更新 |

三者会重叠，但研究时应明确被改进和被评价的是哪一种能力。

## 8. Action Module：Agent 怎样真正影响环境

Action 是架构最下游的模块，将决策变成结果，并直接与环境交互。论文从四个角度分析。

### 8.1 Action Goal：动作目的

- **Task completion**：完成明确任务；
- **Communication**：与人或其他 Agent 交换信息、协作；
- **Environment exploration**：探索未知状态、技能或资源。

同一动作可能服务多个目标。例如向用户提问既是沟通，也是为了减少推荐不确定性。

### 8.2 Action Production：动作怎样产生

- **Memory recollection**：根据当前任务检索历史经验，直接复用或改写；
- **Plan following**：先形成计划，再按计划执行子目标。

风险是“错误记忆驱动错误行动”和“盲目遵守过时计划”。因此成熟 Agent 应允许执行监控和重规划。

### 8.3 Action Space：可以做什么

#### External Tools

- API；
- 数据库/知识库；
- 专用模型；
- 搜索、代码执行或物理执行器。

工具扩展了模型能力，但也带来四种独立错误：

1. 工具选择错；
2. 参数生成错；
3. 工具执行失败；
4. 工具结果被模型误读。

因此不能只评价最终答案，还应记录完整 trajectory。

#### Internal Knowledge

不调用外部工具，依靠 LLM 内部的规划、对话、常识等能力。优点是简单；缺点是知识不可追溯、可能过时或幻觉。

### 8.4 Action Impact：动作产生什么后果

- 改变环境；
- 改变 Agent 内部状态和记忆；
- 触发后续动作；
- 对人产生情绪、信任、依赖或决策影响。

论文主要讨论前三类。对本实验室而言，第四类尤其重要：人机共生研究不能只看“动作成功率”，还要看动作怎样塑造用户和关系。

## 9. Capability Acquisition：能力从哪里来

### 9.1 通过 Fine-tuning 获取能力

论文按数据来源分为：

1. **Human-annotated data**：质量较可控但昂贵；
2. **LLM-generated data**：便宜、规模大，但会继承教师模型错误；
3. **Real-world data**：任务真实性较好，但有噪声、隐私和许可问题。

Fine-tuning 能把大量领域知识和行为模式写入参数，推理时不必全部塞进 Prompt。但它需要可训练模型和数据，也可能过拟合、遗忘通用能力或固化偏见。

### 9.2 不通过 Fine-tuning 获取能力

#### Prompt Engineering

用指令、示例、角色、当前状态和历史经验激发已有能力。适合闭源模型，迭代快；缺点是受上下文长度限制且提示不稳健。

#### Mechanism Engineering

这是论文很有启发性的概念：不一定改变模型参数，也不只改变一句 Prompt，而是改变 Agent 的工作制度。

论文归纳：

- **Trial-and-error**：行动—批评—修正；
- **Crowd-sourcing**：多个 Agent 辩论或汇总；
- **Experience accumulation**：成功轨迹、技能和反馈进入记忆；
- **Self-driven evolution**：Agent 自设目标并在环境中持续提升。

研究时要小心：机制更复杂往往意味着更多模型调用和更大测试时算力。若比较时不给简单 baseline 相同预算，所谓机制提升可能只是“花费更多 token”。

## 10. 应用地图：论文怎样划分 Agent 的使用场景

### 10.1 Social Science

包括心理学、政治与经济、社会模拟、法律和科研辅助。

与实验室最相关的是：

- 用 Agent 模拟人类心理实验；
- 情感支持与心理健康场景；
- 社会关系和群体行为模拟；
- 个性化角色及人机互动。

作者也观察到所谓 **hyper-accuracy distortion**：模型有时给出“过于完美”的估计，而真实人类会有噪声、知识限制和非理性。这说明“模型答案接近实验平均值”不等于“模型真实模拟了人”。

### 10.2 Natural Science

包括文档与数据管理、实验辅助和教育。Agent 可以搜索文献、调用计算工具、生成实验流程，但高风险实验必须由专业人员验证。

### 10.3 Engineering

包括软件工程、工业自动化、机器人与具身智能。这里最能体现 Action：代码执行、API 调用、机器人操作会真正改变环境，因此错误的后果比普通文本回答更大。

### 10.4 为什么应用章节不能只当“案例展示”

每个应用都应重新定义：

- 环境是什么；
- 目标由谁设定；
- 动作权限有多大；
- 反馈是否可靠；
- 失败成本是什么；
- 哪些行为必须由人审批。

一个在游戏中可接受的试错机制，不能原样移植到心理支持、医疗或工业控制。

## 11. Evaluation：怎样判断 Agent 是否有效

### 11.1 Subjective Evaluation

#### Human Annotation

让人对输出或轨迹打分、排序。适合评价自然度、帮助性、共情、角色一致性等难以完全自动化的维度。

风险：

- 成本与速度；
- 标注者群体偏差；
- 评分标准不一致；
- 看到系统身份后产生期望偏差；
- 单轮感受不代表长期效果。

#### Turing Test

让人区分输出来自人还是 Agent。若无法区分，只能说明在该任务和评价条件下“表面像人”，不能证明：

- 输出正确；
- 决策安全；
- 具有理解或主体性；
- 对用户有长期益处。

#### LLM-as-a-Judge

论文已提到用一个或多个 LLM 替代人工评价。优点是便宜、可扩展；主要风险是偏好同源模型、对格式和长度敏感、可能无法识别事实错误。它应和可验证指标、人工抽查结合。

### 11.2 Objective Evaluation

论文分为 metrics、protocols、benchmarks 三层。

#### Metrics

1. **Task success**：成功率、奖励、覆盖率、准确率；
2. **Human similarity**：连贯、流畅、行为相似、接受率；
3. **Efficiency**：开发成本、训练/推理效率等。

必须注意：

- Task success 不等于过程正确；
- Human similarity 不等于对人有益；
- 高效率不等于高质量；
- 单一平均分会隐藏不同任务类型的严重失败。

#### Protocols

- Real-world simulation；
- Social evaluation；
- Multi-task evaluation；
- Software testing。

Protocol 决定指标在什么交互过程里被采集。相同成功率，在离线问答和真实多轮环境中的含义可能完全不同。

#### Benchmarks

论文列举 AgentBench、WebShop、ToolBench、WebArena、SocKET、EmotionBench 等。Benchmark 提供可比较环境，但也会被任务模板、模拟器真实性和训练污染限制。

### 11.3 一个更完整的 Agent 评价矩阵

论文框架可以进一步扩展为：

| 层次             | 评价问题         | 示例                 |
| -------------- | ------------ | ------------------ |
| Outcome        | 最终目标是否完成     | Success Rate、Hit@K |
| Process        | 轨迹是否正确、可解释   | 计划正确率、工具调用错误       |
| Robustness     | 提示、环境变化后是否稳定 | 扰动测试、跨任务泛化         |
| Efficiency     | 花费多少资源       | 延迟、token、调用次数      |
| Human-centered | 人如何感知与受影响    | 信任、满意、共情、依赖        |
| Safety/Ethics  | 是否造成风险       | 隐私泄露、操控、有害建议       |
| Longitudinal   | 长期交互后发生什么    | 偏好漂移、关系与行为变化       |

本实验室的研究若只报告生成质量或成功率，就无法覆盖“人机共生”的核心问题。

## 12. 论文提出的六个挑战

### 12.1 Role-playing Capability

稀有角色、新角色和复杂心理特征难以可靠模拟。人工 Prompt、架构设计和微调都可能改善，但又会带来泛化损失与设计空间过大的问题。

### 12.2 Generalized Human Alignment

传统对齐倾向让模型遵守统一规范；社会模拟却可能需要呈现多样甚至负面的真实行为。问题是怎样在“研究真实性”和“防止危险行为”之间划清边界。

需要批判论文中的极端例子：为了模拟而允许危险规划，并不意味着系统应获得真实执行权限。可研究性、沙箱隔离、访问控制和现实危害必须分开设计。

### 12.3 Prompt Robustness

微小措辞变化可能产生大幅结果差异。Agent 由多个 Prompt 模块串联，一个模块的变化会传播到其他模块，因此系统级鲁棒性比单 Prompt 更难。

### 12.4 Hallucination

Agent 的幻觉比普通聊天更危险，因为它可能被转换成工具调用、代码或真实动作。缓解手段应包括检索、验证、权限控制、人类审批和执行沙箱，而非只要求模型“再检查一次”。

### 12.5 Knowledge Boundary

LLM 拥有远超被模拟普通人的知识，可能在用户模拟中“作弊”。例如模拟一个尚未看过电影的用户时，模型却从预训练中知道电影情节。需要控制 Agent 可使用的知识，否则社会模拟结论失真。

### 12.6 Efficiency

Agent 每一步可能多次调用 LLM：检索、规划、反思、工具选择、评价。长程任务的延迟与费用会快速累积。评价新方法时必须报告调用预算和成本。

## 13. 这篇综述自身的局限

这是阅读综述必须做的一步：综述的分类也只是作者提出的一种观察方式。

### 13.1 时间覆盖较早

核心文献主要集中于 2021–2023 年。后来快速发展的长期记忆评测、Agent 安全、计算机操作 Agent、标准化工具协议和更系统的多智能体评价，在文中覆盖有限或没有覆盖。

### 13.2 “自主”边界较宽

表格纳入一些并未明确称为 Agent 的工作。统一框架因此覆盖面广，但也可能把“带工具的语言模型”“多轮推理系统”和“持续自主 Agent”混在一起。

### 13.3 四模块不是完全正交

- Planning 的中间结果可被保存为 Memory；
- Reflection 同时属于 Memory operation 和反馈式 Planning；
- 工具调用既是 Action，也可用于感知；
- Profile 也可能由长期 Memory 动态形成。

所以四模块适合入门，不应被当作唯一正确的软件边界。

### 13.4 对“人类式”能力的论述需谨慎

论文多次使用 human-like、self-evolve 等表述，但行为相似不等于机制相同。认知科学概念被借用于工程设计时，需要验证构念效度，不能只因用了“短期记忆”“反思”等名称就认为模型具有对应人类心理机制。

### 13.5 评价章节仍较粗

文中强调 subjective/objective 的结合，但对以下问题讨论不够：

- 数据污染；
- 可重复性；
- 置信区间和统计显著性；
- 安全、隐私和长期人类影响；
- 成功结果是否来自不公平的计算预算；
- Agent trajectory 的逐环节诊断。

### 13.6 文献罗列多于因果综合

Survey 为求覆盖面列举大量系统，部分段落更像 catalogue。阅读时不必记住所有系统名，而应抽取“问题—机制—证据—局限”。

## 14. 与实验室 Research Map 的具体对应

### 14.1 面向人机交互的情感智能体

| 实验室问题 | 本文对应模块 | 需要进一步补足 |
|---|---|---|
| 情感陪伴与激励 | Profile、Memory、反馈式 Planning、Communication Action | 情绪状态如何测量，长期改善与风险 |
| 心理咨询理论植入 | Profile、Planning、Capability Acquisition | 理论忠实性、专业边界、伦理 |
| 动态情感智能体 | Hybrid Memory、Experience Accumulation、RL/feedback | 状态漂移、奖励效度、安全约束 |
| AI 主体性测量 | Profile、Action、Social Evaluation | 主体性构念不能由拟人输出直接推出 |
| 人机关系演化 | Long-term Memory、Action Impact | 纵向实验、依赖与信任变化 |

### 14.2 拟人智能体

- Profile：人格和角色；
- Memory：跨轮一致性和经历积累；
- Planning：目标与行为的长期连贯；
- Action：社会行为和工具使用；
- Social evaluation：人格一致性、合作和人类感知。

一个重要研究问题是：人格是否应该是固定 Prompt，还是从互动中动态更新？固定人格容易稳定但僵化；动态人格更真实，却可能漂移或被用户操控。

### 14.3 个性化推荐与决策 Agent

- Profile 表示长期偏好；
- Memory 保存历史行为、对话和偏好更新；
- Planning 决定何时询问、何时推荐、怎样引导；
- Tool/Action 调用检索和推荐模型；
- Evaluation 同时需要推荐准确、对话质量、解释忠实和用户成本。

### 14.4 知识增强 Agent

本文把数据库、知识库和外部模型归入 Action Space，但从今天的视角看，RAG 也可被视为 Memory/Perception 的一部分。这再次说明模块边界取决于系统设计。

### 14.5 多轮人机协作决策

核心是反馈式 Planning：Agent 不应一次性猜完用户需求，而要根据用户反馈更新状态、提出澄清、调用知识并修正计划。

## 15. 读完后必须能区分的概念

### 15.1 Chat History vs Memory

- Chat History：发生过的原始对话；
- Memory：经过选择、表示、写入、更新、检索和使用的历史信息系统。

### 15.2 RAG vs Agent Memory

- RAG 通常面向外部知识检索；
- Agent Memory 常包含自身经历、用户状态、任务轨迹和反思；
- 两者技术可重叠，但知识来源、更新规则与评价目标不同。

### 15.3 Reasoning vs Planning

- Reasoning 关注从前提得到结论；
- Planning 关注为了未来目标组织动作；
- 计划生成需要推理，但推理任务不一定产生行动计划。

### 15.4 Reflection vs Feedback

- Feedback 是信号来源；
- Reflection 是对经历或反馈进行解释、总结和修正的过程。

### 15.5 Tool Use vs Agent

一次 API 调用不自动构成 Agent。Agent 还需目标、状态、选择、反馈和跨时间行为。

### 15.6 Persona vs Personality

- Persona 是系统使用的角色描述或身份信息；
- Personality 是相对稳定的心理特质构念；
- Persona Prompt 能操纵表现，但不能直接证明模型拥有 Personality。

缺少将架构、能力获取、应用和评价放入一体化 taxonomy 的系统总结。

### Core Idea

用“构建—应用—评价”组织领域；用 Profile–Memory–Planning–Action 统一架构；用微调/非微调统一能力获取。

### Method

文献收集、人工分类和叙述性综合。论文并未给出严格系统综述所需的完整检索式、数据库、纳排流程与质量评估，因此更接近 comprehensive narrative survey。

### Dataset

没有传统实验数据集；“数据”是作者收集的约 100 篇相关工作。

### Baseline

Survey 没有模型 baseline；可将之前的 LLM、ALM、reasoning、evaluation surveys 视为相关综述比较对象。

### Metric

没有量化评价 taxonomy 的覆盖率、互标一致性或读者效用。

### Result

形成统一架构、应用分类、评价分类和六个挑战。

### Ablation

无。综述框架也没有通过移除某分类维度来验证必要性。

### Case Study

大量系统被作为分类例子，如 Generative Agents、ReAct、Voyager、ChatDev 等。

### Limitation

时间覆盖早、Agent 边界较宽、模块交叉、评价和伦理讨论相对粗、缺少系统综述方法透明度。

### Relation to Our Lab

四模块几乎覆盖实验室技术关键词；Social Science、Psychology、Social Simulation、Recommendation、Human–Agent Interaction 与两条一级主线直接相关。

## 19. 今日自测与验收

### 19.1 基础题

> 以下为结合本文框架整理的参考答案，不是论文原文；其中的实验设计与工程建议属于延伸理解。

#### 1. 为什么普通 LLM 问答不自动等于 Agent？

**参考答案：** 普通问答主要是“输入问题 → 生成回答”；自主 Agent 则围绕目标，根据环境观察选择行动，并利用行动结果继续推进任务。关键区别不是有没有聊天界面，而是有没有目标导向的决策和行动过程。

例如，“告诉我怎样分析销量”是问答；“查询销量数据、分析原因、发现缺失后继续补查，最后生成报告”更接近 Agent。记忆、规划和工具可以支持这个过程，但不要求每个 Agent 都有四个独立模块，也不要求所有行动都调用外部工具。

#### 2. Profile、Memory、Planning、Action 各自的输入和输出是什么？

**参考答案：** 可以按“角色 → 信息 → 计划 → 执行”理解：

| 模块 | 典型输入 | 典型输出 |
|---|---|---|
| Profile：我是谁 | 指定角色、任务职责、行为规则、权限限制 | 角色描述、行为约束或用于后续决策的角色条件 |
| Memory：我知道、经历过什么 | 对话、观察、行动结果、历史记录，以及当前检索请求 | 保存或更新的记忆、当前任务需要的相关信息 |
| Planning：接下来怎么做 | 目标、角色约束、相关记忆、当前状态和反馈 | 子目标、步骤顺序、候选方案或下一步决策 |
| Action：实际做什么 | 选定动作、工具说明、参数和执行环境 | 工具调用、消息或其他环境动作，以及执行结果 |

这些是功能上的划分，不一定对应四段独立程序。行动结果可以成为下一轮观察，进入记忆并触发重新规划。

#### 3. 为什么完整对话历史不等于长期记忆系统？

**参考答案：** 对话历史只是记录；长期记忆系统还要决定哪些信息值得保存、怎样检索、如何更新、怎样处理冲突，以及何时删除或遗忘。

把全部历史塞进上下文，会遇到窗口限制、成本增长和无关信息干扰。即使把聊天记录长期保存到文件里，也不代表模型每次都能找到并正确使用它。因此，“保存了历史”可以是记忆系统的基础，但不等于已经具备有效的长期记忆管理。

#### 4. Unified Memory 与 Hybrid Memory 的差别是什么？

**参考答案：** 按本文的具体分类：

- **Unified Memory：** 主要模拟短期记忆，把信息直接放进当前上下文，供模型使用。像只有一张工作纸。
- **Hybrid Memory：** 结合短期与长期记忆，把当前任务放在上下文中，把历史经历、偏好和经验等保存在长期存储里，需要时检索回来。像“工作纸＋档案库”。

两者都不必修改模型参数。Hybrid 中的长期记忆通常保存在模型外部，不等于写入权重。这里的 Unified 是本文语境下的用法，不宜泛化成所有系统中的统一记忆定义。

#### 5. Memory Reading 的 recency、relevance、importance 分别解决什么？

**参考答案：** 三者分别回答：

- **Recency（新近程度）：** 信息是否最近产生或访问？通常用时间衰减计算，帮助关注近期情境。
- **Relevance（相关度）：** 信息是否与当前问题有关？可以用向量相似度或重排模型估计。
- **Importance（重要性）：** 信息本身是否值得长期重视？可以由规则、人工或模型根据明确标准评分。

例如，“昨天吃了面条”很新，但对制定促销方案没用；“三个月前确定店铺不做低价竞争”虽然旧，却相关且重要。合并评分前要统一尺度，权重应通过任务验证调整，不存在通用最佳值。必须遵守的权限与经营红线不应只依赖检索排名。

#### 6. 单路径和多路径规划的主要权衡是什么？

**参考答案：** 单路径沿一条思路推进，通常成本低、速度快，但早期错误容易传递到后续步骤；多路径生成多个候选方案，再比较、投票或搜索，有机会避开局部错误，但需要更多计算和可靠的选择机制。

多路径不保证更好：多个候选可能犯同一种错，评价器也可能选错。比较两者时，应同时看成功率、token 消耗、调用次数和延迟，而不能只看最终准确率。

#### 7. Environment、Human、Model feedback 各自有什么优缺点？

**参考答案：**

| 反馈来源 | 例子 | 优点 | 局限 |
|---|---|---|---|
| Environment：环境反馈 | 工具报错、程序测试结果、任务奖励 | 能提供实际执行证据，部分结果可自动核验 | 可能稀疏、延迟或有噪声；局部成功不等于整体成功 |
| Human：人类反馈 | 用户指出偏好错误，专家修改计划 | 能表达复杂意图、价值判断和细微质量差异 | 成本高、速度慢，评价者可能存在分歧或偏差 |
| Model：模型反馈 | 模型自检、另一个模型评价方案 | 易自动化，能快速给出修改建议 | 可能重复原有错误，或给出听起来合理却错误的批评 |

三者可以互补。收到反馈只表示获得了新信息；如果只是将反馈放入上下文，并没有因此自动发生参数更新或强化学习训练。

#### 8. Tool use 会在哪四个阶段出错？

**参考答案：** 可以记成“选错、填错、没执行成、读错”。以“查询商品 A 昨天销量”为例：

1. **工具选择错：** 应查销量，却选择查询库存。
2. **参数生成错：** 工具选对，但商品编号或日期填错；也可能缺少参数或格式错误。
3. **工具执行失败：** 请求正确，但网络超时、服务不可用、权限不足等导致失败。
4. **工具结果被误读：** 数据正确返回，却把销售额当销量，或者把“无数据”理解成“零销量”。

这些阶段可能有因果联系，例如错误参数导致执行报错。诊断时应区分根因，不能只看到报错就认定是服务故障。工具调用成功也不等于最终回答正确。

#### 9. Fine-tuning、Prompt Engineering、Mechanism Engineering 的差别是什么？

**参考答案：**

- **Fine-tuning（微调）：** 通过进一步训练更新模型参数。像专项培训，把能力调整落实到模型内部。
- **Prompt Engineering（提示词工程）：** 改善任务说明、示例、约束和输出格式，通常不更新参数。像把工作说明写清楚。
- **Mechanism Engineering（机制工程）：** 设计工具使用、记忆检索、规划、反馈、审核与协作流程，让系统整体更有效。像建立配套工作制度。

例如，训练模型更擅长分析报表是微调；要求它逐项列出数据依据是提示词工程；让它自动查询数据、运行校验、失败后重试是机制工程。三者可以组合使用，提示词和机制的边界也不是绝对的。

#### 10. Subjective 与 Objective evaluation 为什么需要结合？

**参考答案：** 客观指标擅长检查可核验结果，例如正确率、成功率、成本和延迟；主观评价擅长判断帮助性、自然度、共情和体验等难以被单一数值完整表达的质量。

报告可能写得很贴心但数据错误，也可能计算正确却难以理解。只看任何一边都会漏掉问题。因此应结合可核验测试、人类评价和必要的长期观察，同时记录评价标准、分歧和适用情境。两类评价也不是完全隔离的，例如可以对用户体验采用标准化量表。

### 19.2 进阶题

#### 1. 如果检索 Recall@5 很高但回答准确率低，可能是哪一模块失败？

**参考答案：** 高 Recall@5 只说明标准相关记忆大多进入了前五条候选，不说明模型已经正确读懂、组合并使用这些证据。失败可能出现在：

- **上下文构建：** 找到了证据，但注入时被截断、遗漏或压缩失真。
- **记忆质量与更新：** 检索到了相关但错误、过期或互相冲突的记录。
- **阅读与推理：** 忽略关键证据，混淆时间、人物、否定关系，或多跳组合失败。
- **规划与行动：** 证据不足时没有补查，或后续工具参数填错、结果读错。
- **回答生成：** 推理已有依据，但输出时仍加入无证据内容。

因此不能直接归因于某一个模块。可把人工核验的完整证据直接提供给模型，检查准确率是否提高，再逐步排查检索后的上下文、推理和生成过程；同时检查 Recall 的标注是否真的覆盖回答所需的全部证据。

#### 2. 把人格写入 Prompt 后，怎样证明产生的是稳定人格而非表面措辞？

**参考答案：** 不能只凭几句“像某种人格”的语言就下结论，应检查人格设定能否持续影响行为选择。

可设计以下验证：

1. **跨情境：** 在合作、冲突、资源分配和不确定决策等不同任务中测试同一特征。
2. **跨时间：** 进行多轮、跨会话测试，观察长期一致性；跨会话时需说明是否重新提供人格设定和记忆。
3. **行为而非措辞：** 除了评价语气，还观察风险选择、履约、协作等决策，且不把某种选择当成人格的唯一证明。
4. **对照与盲评：** 比较无人格提示、不同人格提示以及只改变语言风格的条件，让评价者不知道分组。
5. **重复与扰动：** 多次采样，改变措辞、任务和干扰条件，检查结果是否稳健。

这些只能支持“在规定条件下具有稳定的人格化行为”，不能证明它拥有人的内在人格、感受或主体性。

#### 3. 多 Agent 辩论效果更好，如何排除只是使用了更多计算预算？

**参考答案：** 设置计算预算相近的基线，而不是只与“单 Agent 回答一次”比较。

- 单 Agent 使用同等预算进行多次独立采样、投票、自我反思或多路径搜索。
- 控制基础模型、工具权限、输入信息和测试任务，避免把模型差异误当成协作收益。
- 记录总输入与输出 token、模型调用次数、工具成本，以及实际延迟；并行执行还要区分总计算量与墙钟时间。
- 在多个预算档位下比较质量—成本曲线，而不是只挑一个有利点。
- 做消融实验：去掉讨论、角色分工或互相可见的消息，观察性能是否下降。

只有在预算和其他条件受到合理控制后，辩论仍稳定优于强基线，才能更有依据地把收益归因于交互机制；仍需报告重复实验和不确定性。

#### 4. 一个 Agent 推荐命中目标物品但用户不满意，现有指标遗漏了什么？

**参考答案：** 命中指标通常只检查是否推荐了数据集中标记的目标物品，未必覆盖用户完整需求，也未必代表用户现在真正想要它。

可能遗漏：价格与库存约束、推荐时机、近期偏好变化、多样性与新颖性、解释是否可信、交互是否费力，以及用户对隐私或过度推销的反感。历史购买也不一定等于喜欢，可能只是替别人购买。

应结合显式约束满足率、推荐多样性、用户满意度、交互轮数、退货或后悔情况等指标，并通过用户研究和长期观察验证。点击或购买可以提供信息，但不能单独等同于满意和长期受益。

#### 5. Reflection 可能怎样放大而不是修正错误？

**参考答案：** Reflection 是对经历的归纳，不自带事实保证。模型可能把一次误解压缩成错误结论，再反复引用它。

例如：用户今天不想聊天 → 总结成“用户性格冷漠” → 后续减少互动 → 将互动减少又当作该结论的证据。一次临时状态就被固化成长期人格判断。

其他风险包括：总结时丢掉条件与否定词、把相关性误写成因果、多个总结互相引用造成虚假佐证，以及删除原始记录后无法追溯。

可保留证据来源、时间和不确定性，区分观察事实与推测，允许用户更正，并对重要总结做独立验证。反思的效果也应通过实验检验，而不是因为文本更像分析就认为它更准确。

#### 6. 社会模拟中的 Agent 为什么可能表现得“过于完美”？

**参考答案：** 模型常被训练成提供连贯、合作、条理清晰的回答，而真实的人会遗忘、分心、误解，受到有限信息、情绪、利益和资源约束影响。如果模拟只保留理想化语言行为，就可能高估合作效率和理性程度。

此外，多个 Agent 可能使用同一个基础模型，思维模式过于相似；系统也可能给它们现实中不可能知道的全局信息，或让它们几乎零成本地沟通。

应限制各角色可见信息、时间与资源，建模异质性和合理的认知限制，并与真实人类行为数据比较。不能简单随机添加错误就宣称模拟真实；这些设定也需要校准和验证。

#### 7. 论文把知识库归入 Action，你是否可以把它归入 Memory？两种划分分别强调什么？

**参考答案：** 可以，取决于分析的是知识的存储角色，还是获取知识的行为。

- **归入 Memory：** 强调知识库作为持久信息存储，关注表示、索引、更新、检索和遗忘。
- **归入 Action：** 强调 Agent 主动调用搜索或查询接口，与外部系统交互来获取知识。

例如，“查询店铺退货政策”是一个 Action；政策文档是外部知识资源，也可以纳入广义 Memory；查询结果进入当前上下文后，又成为本轮可用信息。

因此两种划分不必冲突：同一个流程可以同时涉及记忆与行动。关键是明确系统边界和分类目的，而不是把每个组件强行塞进唯一的格子。

### 19.3 最终口述验收

不看笔记，用一个“长期个性化情感陪伴 Agent”例子讲清：

- 它的 Profile 是什么；
- 它写入和读取哪些 Memory；
- 它怎样 Planning；
- 它能执行哪些 Action；
- 它从哪里获取能力；
- 怎样评价短期质量、长期效果、成本和风险。

如果能在 8–10 分钟内讲清，并指出至少三个潜在失败点，就达到了第一篇论文的学习目标。
