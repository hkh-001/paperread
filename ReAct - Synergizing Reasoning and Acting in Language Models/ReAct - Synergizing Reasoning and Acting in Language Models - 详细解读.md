> 论文：**ReAct: Synergizing Reasoning and Acting in Language Models**  
> 会议：ICLR 2023  
> 作者：Shunyu Yao 等

## 0. 为什么把它作为第二篇论文

上一篇综述帮助我们建立了 LLM Agent 的全景地图：一个智能体通常需要感知、记忆、规划、行动、工具使用和反馈闭环。ReAct 则把这张地图中最关键的一条连接具体化：

> **模型不是先把所有推理做完再行动，也不是完全不思考地连续行动；它可以在“思考—行动—观察”之间循环。**

这篇论文适合作为第二篇，原因有四个：

1. **概念清楚。** 方法核心可以用一个循环解释，适合从综述进入具体论文。
2. **影响深远。** 今天大量 Agent 框架中的“Thought / Action / Observation”轨迹都直接或间接受 ReAct 影响。
3. **覆盖面广。** 它同时研究知识问答和交互式决策，能让我们看到“调用搜索工具”与“在环境里完成任务”的共同结构。
4. **可批判。** 它既有重要洞见，也暴露了循环、错误累积、推理忠实性、工具安全和复现等问题，适合训练科研判断力。

建议今天不要只记“ReAct = Reason + Act”。真正要理解的是：

- 为什么纯 Chain-of-Thought 不够；
- 为什么纯 Action 不够；
- 外部观察如何改变后续推理；
- 推理轨迹怎样成为一种临时工作记忆；
- 论文中的“可解释”究竟意味着什么，又不意味着什么。

## 1. 一句话、三句话和一段话概括

### 1.1 一句话版

ReAct 让语言模型在同一条轨迹中交替生成自然语言推理和面向环境的动作，用外部反馈修正推理，再用推理指导下一步行动。

### 1.2 三句话版

1. 只做语言推理的模型容易依赖内部参数知识，出现事实幻觉，而且无法主动获取新信息。
2. 只输出动作的模型缺少显式任务分解、进度跟踪和异常处理，因此容易盲目尝试或陷入循环。
3. ReAct 把 Thought、Action、Observation 串成闭环，在问答任务上降低幻觉，在交互任务上提高成功率。

### 1.3 一段话版

论文将语言模型看成一个策略：模型根据截至当前时刻的交互历史决定下一步输出。传统智能体只从外部动作集合中选择动作，ReAct 则把“语言形式的思考”也加入模型的可输出空间。思考不会直接改变环境，却会改变模型下一步决策所依赖的上下文；外部动作会改变环境或查询外部知识，并返回新的观察。如此反复，模型便能够分解目标、制定计划、记录进度、发现异常、检索知识并根据真实反馈修正计划。

## 2. 论文试图解决什么问题

### 2.1 两条此前相对分离的研究路线

论文认为，在它发表前，语言模型能力主要沿两条路线展开。

#### 路线 A：语言推理

典型方法是 Chain-of-Thought（CoT）。模型在给最终答案前生成一串中间推理步骤。

优点：

- 能分解复杂问题；
- 对算术、多跳推理、常识推理等任务有效；
- 中间文本便于人观察。

局限：

- 推理主要依赖参数中已经存储的知识；
- 无法验证自己刚刚说的事实；
- 一旦前面的事实或中间步骤错误，后续推理可能在错误前提上继续展开；
- “看起来有道理”不代表内容真实。

#### 路线 B：交互式行动

另一类工作让模型或策略直接在环境中行动，例如玩文字游戏、控制网页、操作机器人或调用工具。

优点：

- 能得到真实环境反馈；
- 能完成不只是“回答问题”的任务；
- 行动结果可直接检验。

局限：

- 如果策略不显式推理，它可能不知道当前子目标是什么；
- 容易重复失败动作；
- 难以处理长时程依赖和异常；
- 人只能看到动作，很难理解为什么这么做。

### 2.2 ReAct 的核心研究问题

> 如果让语言模型把“推理”和“行动”放到同一条生成轨迹中，二者能否互相补足？

论文的回答是肯定的：

- 推理帮助行动：分解任务、选择工具、记录状态、调整计划；
- 行动帮助推理：搜索事实、探索环境、验证假设、提供新证据；
- 观察连接二者：把外部世界的结果重新写入语言模型上下文。

这构成一个最小的智能体闭环：

```text
任务/目标
   ↓
Thought：我现在知道什么？下一步缺什么？
   ↓
Action：搜索、查询、移动、点击、拿取……
   ↓
Observation：工具或环境返回了什么？
   ↓
Thought：结果是否支持原计划？需要修改吗？
   ↓
……直到 Finish
```

## 3. 先用一个直观例子理解 ReAct

假设问题是：

> 《指环王》作者与《哈利·波特》作者中，谁出生得更早？

### 3.1 纯 CoT 可能怎样做

```text
Thought: 《指环王》的作者是托尔金，生于 1892 年。
《哈利·波特》的作者是 J. K. Rowling，生于 1965 年。
因此托尔金更早。
Answer: 托尔金。
```

如果模型记忆正确，答案正确；但它没有验证出生年份。遇到冷门人物时，可能编造一个很像真的年份。

### 3.2 纯 Action 可能怎样做

```text
Action: search[The Lord of the Rings]
Observation: ...
Action: search[Harry Potter]
Observation: ...
Action: search[J. K. Rowling]
Observation: ...
Action: search[J. R. R. Tolkien]
Observation: ...
```

它能获取信息，但缺少显式说明：为什么查这些实体、目前得到什么、还差什么。复杂任务中更容易偏航。

### 3.3 ReAct 怎样做

```text
Thought: 需要先确定两部作品的作者，再比较两位作者的出生日期。
Action: search[The Lord of the Rings]
Observation: 页面显示作者为 J. R. R. Tolkien。
Thought: 已得到第一位作者，接下来确认其出生日期。
Action: lookup[born]
Observation: Tolkien was born on 3 January 1892 ...
Thought: 现在查《哈利·波特》的作者及出生日期。
Action: search[Harry Potter]
Observation: ... written by J. K. Rowling ...
Action: search[J. K. Rowling]
Observation: ... born 31 July 1965 ...
Thought: 1892 早于 1965，所以答案是 Tolkien。
Action: finish[J. R. R. Tolkien]
```

关键不是文本中多了几个标签，而是形成了一个**由真实反馈驱动的控制循环**。

## 4. 方法的形式化定义与公式精讲

这一节是全文最值得精读的部分。

### 4.1 环境、观察和动作

在时间步 $t$，智能体接收到观察：

$$
o_t \in \mathcal{O}
$$

其中：

- $t$：当前交互步；
- $o_t$：这一步看到的内容；
- $\mathcal{O}$：所有可能观察构成的空间。

观察可以是：

- 搜索接口返回的一段 Wikipedia 文本；
- 网页当前显示的商品信息；
- 文字环境对“打开冰箱”的反馈；
- 工具执行结果或报错。

智能体随后选择动作：

$$
a_t \in \mathcal{A}
$$

$\mathcal{A}$ 是外部动作集合。例如：

```text
search[entity]
lookup[string]
finish[answer]
```

或者：

```text
go to fridge 1
open fridge 1
take apple 1 from fridge 1
```

### 4.2 上下文是什么

模型做第 $t$ 步决策时，并非只看当前观察，而是看至今为止的整段交互历史：

$$
c_t = (o_1, a_1, o_2, a_2, \ldots, o_{t-1}, a_{t-1}, o_t)
$$

论文的排版也可写作：

$$
c_t = (o_1, a_1, \ldots, o_{t-1}, a_{t-1}, o_t)
$$

这里的 $c_t$ 可以理解为模型的**当前工作记忆**：它包含任务、此前动作、环境反馈以及稍后加入的思考。

注意：

- 它不是持久化数据库意义上的长期记忆；
- 它受上下文窗口限制；
- 信息是否被有效利用，取决于模型的注意力与提示结构；
- 历史越长，成本越高，也越可能出现早期信息被忽略的问题。

### 4.3 策略：下一步做什么

智能体的策略写成：

$$
\pi(a_t \mid c_t)
$$

它表示：给定当前上下文 $c_t$，策略对下一动作 $a_t$ 给出一个条件概率分布。

对语言模型而言，可以把动作串也视作待生成的 token 序列。因此，LLM 既是语言生成器，也是策略的参数化实现。

逐 token 写，可进一步理解为：

$$
P(a_t \mid c_t)
= \prod_{i=1}^{|a_t|}
P(a_{t,i} \mid c_t, a_{t,<i})
$$

其中：

- $a_{t,i}$ 是本次动作文本的第 $i$ 个 token；
- $a_{t,<i}$ 是该动作中先前生成的 token；
- 最终的动作命令，是语言模型自回归生成的字符串，经解析后交给工具或环境。

这不是论文重点展开的公式，但它有助于理解：ReAct 并没有另外训练一个传统控制器；它利用语言模型生成结构化文本，再把文本映射成环境动作。

### 4.4 最关键的一步：扩展动作空间

ReAct 将原本的外部动作集合 $\mathcal{A}$ 扩展为：

$$
\hat{\mathcal{A}} = \mathcal{A} \cup \mathcal{L}
$$

其中：

- $\mathcal{A}$：真正作用于外部环境的动作；
- $\mathcal{L}$：语言空间；
- $\hat{\mathcal{A}}$：模型现在可选择的完整输出空间。

如果模型在某一步输出：

$$
\hat{a}_t \in \mathcal{L}
$$

那么它输出的是一段 Thought，而不是外部动作。

### 4.5 Thought 为什么也叫“动作”

Thought 不改变外部环境，也不会产生新的外部观察。它的作用是把一段语言写进上下文：

$$
c_{t+1} = (c_t, \hat{a}_t)
$$

也就是说，思考改变的是智能体的**内部语言状态**。下一步生成时，模型可以读取刚才写下的计划、子目标或总结。

一个容易忽略但很重要的结论是：

> ReAct 的 Thought 可以被理解为一种“外显化的工作记忆写入操作”。

例如：

```text
Thought: 我已经找到杯子；下一步应先清洗，再放到桌子上。
```

这句话没有移动任何物体，但它把“已完成什么、下一步是什么”保留在上下文中，从而影响未来动作概率。

### 4.6 Thought、Action、Observation 的因果角色

三者不要混为一谈：

| 类型 | 谁产生 | 是否改变外部环境 | 是否带来新外部信息 | 主要作用 |
|---|---|---:|---:|---|
| Thought | 语言模型 | 否 | 否 | 规划、分解、总结、跟踪、异常处理 |
| Action | 语言模型选择，环境执行 | 是或发起查询 | 通常会 | 搜索、移动、点击、操作、提交答案 |
| Observation | 环境或工具 | 不适用 | 是 | 把执行结果、证据、失败信息返回给模型 |

ReAct 的基本循环可以抽象为：

$$
T_t = f_\theta(c_t)
$$

$$
A_t = g_\theta(c_t, T_t)
$$

$$
O_{t+1} = E(A_t)
$$

$$
c_{t+1} = c_t \oplus T_t \oplus A_t \oplus O_{t+1}
$$

这里是为了教学而做的等价分解，并非论文原样给出的四条公式：

- $f_\theta$：模型生成思考；
- $g_\theta$：模型生成动作；
- $E$：环境转移或工具执行函数；
- $\oplus$：把新内容追加到上下文。

### 4.7 ReAct 不是严格规定每一步都必须先 Thought 再 Action

论文强调它是灵活的：不同任务可以采用不同思考密度。

- 知识问答需要频繁分析证据，所以采用密集的 Thought–Action–Observation 交替。
- 具身或网页任务的很多连续动作十分直接，因此只在关键节点插入稀疏 Thought。

因此，不应把 ReAct 误读成僵硬模板：

```text
每个动作前必须写一大段推理
```

更准确的理解是：

```text
当规划、状态总结、纠错或决策需要时，允许策略显式生成语言推理。
```

## 5. ReAct 中的 Thought 到底承担什么功能

论文列出多种功能，可归纳为六类。

### 5.1 目标分解

把“完成整个任务”拆成可执行子目标。

```text
总目标：把干净的刀放在柜台上
子目标 1：找到刀
子目标 2：找到水槽
子目标 3：清洗刀
子目标 4：把刀放到柜台
```

### 5.2 制定与修改计划

先决定大致路线，在新观察与预期不符时更新。

### 5.3 注入常识

例如“清洗物体通常需要水槽”“冷藏食品通常在冰箱中”。这能缩小探索空间，但也可能把错误常识带入决策。

### 5.4 从观察中抽取关键信息

网页或环境返回往往很长。Thought 可以把它压缩成：

```text
当前商品颜色正确，但材质不符合要求。
```

这相当于有损的信息摘要。

### 5.5 进度跟踪

记录哪些约束已满足、哪些步骤已完成，避免遗忘。

### 5.6 处理异常

当动作失败时，解释失败原因并尝试替代方案，而不是机械重复相同动作。

## 6. 四种主要方法的区别

| 方法       | 有显式推理 | 有外部行动/检索 | 能获取新证据 | 典型风险                |
| -------- | ----: | -------: | -----: | ------------------- |
| Standard |     否 |        否 |      否 | 直接猜答案               |
| CoT      |     是 |        否 |      否 | 在错误事实上继续推理、幻觉       |
| Act      |     否 |        是 |      是 | 缺少规划、易循环、难追踪状态      |
| ReAct    |     是 |        是 |      是 | 搜索失败、推理错误、轨迹变长、错误累积 |

### 6.1 Standard

直接从输入映射到答案，不保留可观察的中间推理与工具交互。

### 6.2 Chain-of-Thought

允许生成推理轨迹，但所有事实主要来自模型内部参数记忆。它会“想”，却不会去外界核验。

### 6.3 Act

只保留动作和观察，删除示例中的 Thought。它会与环境交互，却没有显式语言状态来组织行动。

### 6.4 ReAct

同时保留 Thought、Action 和 Observation，使推理与交互形成闭环。

要注意，ReAct 不是说另外三者在任何条件下都更差。论文结果恰恰显示：不同任务、不同模型规模和不同提示方式下，优势并不完全一致。

## 7. 实验一：知识密集型推理任务

### 7.1 HotpotQA

HotpotQA 是多跳问答任务。回答问题通常需要找到并连接来自不同页面的多个事实。

例如：

1. 找到某部作品的导演；
2. 再找到该导演的出生地；
3. 最后回答出生地属于哪个国家。

这正适合测试：模型能否决定“下一条需要查什么”。

### 7.2 FEVER

FEVER 是事实核验任务。给定一条陈述，模型判断它是否被证据支持或反驳。

任务重点不只在输出标签，更在于找到足以支持判断的外部证据。

### 7.3 工具动作空间

论文为模型提供一个较简单的 Wikipedia 接口：

#### `search[entity]`

搜索一个实体，返回相应页面的开头若干句；如果没有精确页面，则返回相似候选。

#### `lookup[string]`

在当前页面中查找包含指定字符串的下一句话。

#### `finish[answer]`

提交最终答案并结束轨迹。

这个接口有意设计得比较弱。它不是强大的现代检索系统，而是为了观察模型能否通过多步搜索和推理完成任务。

### 7.4 Few-shot 提示设置

论文主要使用冻结的 PaLM-540B，通过上下文示例诱导行为，并没有为了主要结果重新训练模型。

- HotpotQA：6 条人工 ReAct 轨迹；
- FEVER：3 条人工 ReAct 轨迹。

这意味着 ReAct 最初首先是一种**轨迹格式与提示策略**，而不是必须改网络结构的新模型。

## 8. 知识任务的主要结果

以下为论文 Table 1 的核心数字：

| 方法 | HotpotQA EM ↑ | FEVER Accuracy ↑ |
|---|---:|---:|
| Standard | 28.7 | 57.1 |
| CoT | 29.4 | 56.3 |
| CoT-SC | 33.4 | 60.4 |
| Act | 25.7 | 58.9 |
| ReAct | 27.4 | 60.9 |
| CoT-SC → ReAct | 34.2 | **64.6** |
| ReAct → CoT-SC | **35.1** | 62.0 |
| 当时监督学习 SOTA | 67.5 | 89.5 |

### 8.1 先不要急着说“ReAct 全面胜出”

在 HotpotQA 上：

- 单独 ReAct 为 27.4；
- CoT 为 29.4；
- CoT-SC 为 33.4。

所以，ReAct 单独使用并没有在 HotpotQA 上超过 CoT。它的主要优势是降低事实幻觉并提供外部证据，但受限于弱搜索接口和轨迹结构，灵活推理能力可能受到影响。

在 FEVER 上，ReAct 的 60.9 略高于 CoT-SC 的 60.4，但差距很小。最好的结果来自两类方法的组合。

### 8.2 Self-Consistency 是什么

CoT-SC 即 Chain-of-Thought with Self-Consistency：

1. 对同一问题以一定随机性采样多条推理轨迹；
2. 得到多个最终答案；
3. 用多数投票选答案。

论文中采样 21 条 CoT 轨迹，温度为 0.7。

直觉上，它通过“多次独立思考 + 投票”减小单条推理偶然出错的影响，但代价是推理成本显著增加。

### 8.3 两种组合策略

#### ReAct → CoT-SC

先运行 ReAct；如果在规定步数内没有得到答案，则回退到 CoT-SC。

- HotpotQA 最多 7 步；
- FEVER 最多 5 步。

#### CoT-SC → ReAct

先采样多条 CoT；如果多数答案不够一致，即最高票少于样本数的一半，则回退到 ReAct 去检索外部证据。

### 8.4 组合为何有效

两种方法的失败模式不同：

- CoT 更灵活，但容易在事实层面幻觉；
- ReAct 更有事实依据，但可能因检索失败或固定交互结构而失败。

组合的本质是一个**基于不确定性或执行失败的路由器**：先用一种方法，检测风险，再切换到另一种方法。

这启发了后续 Agent 系统设计：不一定让单个策略处理所有情况，而可以让系统根据失败信号选择搜索、重试、反思或替代策略。

### 8.5 与监督学习 SOTA 的差距

即使最佳组合也远低于当时的监督学习 SOTA：

- HotpotQA：35.1 对 67.5；
- FEVER：64.6 对 89.5。

所以论文的贡献不是宣称全面击败专用系统，而是证明一个通用语言模型可以通过少量轨迹示例呈现新的推理—行动协同行为。

## 9. 错误分析：ReAct 真正改善了什么

作者分别分析 ReAct 和 CoT 各 50 个成功案例、50 个失败案例，共 200 条轨迹。

### 9.1 成功案例中的错误

| 类型 | ReAct | CoT |
|---|---:|---:|
| 真正正确（True Positive） | 94% | 86% |
| 虽碰巧答对但推理/事实有问题（False Positive） | 6% | 14% |

即使最终答案正确，中间过程也可能有错误。ReAct 的成功答案更常建立在有效证据之上。

### 9.2 失败案例中的原因

| 失败原因 | ReAct | CoT |
|---|---:|---:|
| 推理错误 | 47% | 16% |
| 搜索错误 | 23% | 不适用 |
| 幻觉 | 0% | 56% |
| 标签/问题歧义等其他因素 | 29% | 28% |

由于百分比取整，合计可能不是严格 100%。

### 9.3 关键结论

ReAct 几乎消除了作者在这组失败样本中认定的事实幻觉，但产生了两类新问题：

1. **搜索错误。** 查错实体、搜索词不合适、没找到关键页面。
2. **推理错误。** 虽拿到证据，却没有正确连接，或被固定的交互过程限制。

这说明外部工具不是“自动正确性按钮”。工具把错误类型从“凭空编造”部分转移成了“查询、选择、解释和整合证据时出错”。

### 9.4 搜索为何会失败

可能原因包括：

- 实体名称消歧失败；
- 查询过宽或过窄；
- 搜索结果顶部不是目标页面；
- `lookup` 关键词和原文措辞不一致；
- 某一步误判导致后续围绕错误实体继续搜索；
- 达到步数上限前仍未找到证据；
- 模型陷入相似查询的循环。

现代 RAG/Agent 研究因此会进一步关注 query rewriting、reranking、多路召回、证据压缩、引用校验和终止条件。

## 10. 微调实验：小模型能否学会 ReAct 轨迹

作者不只做了 few-shot prompting，还使用由 PaLM-540B 生成且最终正确的 3,000 条轨迹，分别训练较小的 PaLM-8B 和 PaLM-62B。

### 10.1 核心发现

- 微调后的 PaLM-8B ReAct 可以超过以提示方式运行的 PaLM-62B；
- 微调后的 PaLM-62B ReAct 可以超过以提示方式运行的 PaLM-540B；
- 结构化的推理—行动轨迹能够被蒸馏到更小模型中。

### 10.2 训练设置

论文附录给出的主要设置包括：

- batch size：64；
- PaLM-8B 的 ReAct/Act：训练 4,000 steps；
- PaLM-8B 的 Standard/CoT：训练 2,000 steps；
- PaLM-62B 的 ReAct/Act：训练 4,000 steps；
- PaLM-62B 的 Standard/CoT：训练 1,000 steps。

作者观察到 Standard/CoT 继续训练可能性能下降，因此采用不同训练步数。

### 10.3 需要谨慎解释

“小模型超过大模型”并不意味着模型规模不重要，而是比较中同时变化了：

- 是否微调；
- 训练数据是否包含正确轨迹；
- 输出格式是否提供了结构化监督；
- 模型规模。

更准确的结论是：**高质量的过程轨迹监督可以显著弥补模型规模差距。**

### 10.4 潜在的数据偏差

训练集只保留“最终答对”的 ReAct 轨迹，会带来选择偏差：模型主要学习成功路径，却较少学习如何从失败中恢复。后续研究可以加入失败轨迹、错误标签、恢复示范和偏好优化。

## 11. 实验二：ALFWorld 交互式决策

### 11.1 ALFWorld 是什么

ALFWorld 是文字形式的具身环境。智能体通过自然语言命令在家庭场景中完成任务，例如：

- 找到某件物品；
- 清洁、加热或冷却物品；
- 把物品放到指定位置；
- 完成包含多个前置条件的长时程任务。

环境具有：

- 6 类任务；
- 50 多种可能位置；
- 专家轨迹可能超过 50 个动作；
- 物体位置和环境布局会变化。

论文在 134 个未见过的游戏实例上评估。

### 11.2 提示设置

每种任务提供 3 条人工标注轨迹，并通过组合形成 6 组提示。论文报告平均结果与最佳提示结果，以反映提示示例选择带来的波动。

### 11.3 结果

| 方法 | 平均成功率 | 最佳成功率 |
|---|---:|---:|
| Act | 45 | 45 |
| ReAct | **57** | **71** |
| ReAct-IM | 48 | 53 |
| BUTLERg | — | 22 |
| BUTLER | — | 37 |

ReAct 最佳成功率比 Act 高 26 个百分点，并明显超过论文引用的模仿学习和强化学习基线。

论文摘要概括为：在 ALFWorld 上取得 34 个百分点的绝对成功率提升，比较对象是当时相关强基线；阅读时要注意摘要与表格中的具体比较基准不完全相同。

### 11.4 一个典型成功轨迹

任务大致是：找到一把刀，清洗它，再放到柜台上。

ReAct 会显式跟踪：

```text
Thought: 先找到刀。
Action: go to drawer ...
Observation: ... knife ...
Thought: 已经取得刀。它需要被清洗，所以应前往水槽。
Action: go to sink ...
Observation: ...
Action: clean knife ...
Observation: knife is clean
Thought: 清洗完成，现在放到柜台。
Action: go to countertop ...
Action: put knife ...
```

Act 基线可能在错误位置尝试 `clean`，动作失败后仍重复类似命令；因为它没有显式保存“为什么失败、下一步应先移动到水槽”。

## 12. 实验三：WebShop 网页购物

### 12.1 任务是什么

WebShop 是一个模拟电商网站环境：

- 约 118 万件商品；
- 约 1.2 万条人类购物指令；
- 测试集包含 500 条指令。

用户指令往往同时包含多个约束，例如：

```text
寻找某类别商品，颜色必须是蓝色，材质必须为棉，预算低于某价格，并满足某用途。
```

智能体需要搜索、点击商品、比较属性、选择选项并购买。

### 12.2 两项指标

#### Score

衡量所购买商品满足目标属性的程度。部分满足也可以得到部分分数。

#### Success Rate

只有当全部要求都满足时才算成功，因此更严格。

### 12.3 结果

| 方法 | Score ↑ | Success Rate ↑ |
|---|---:|---:|
| Act | 62.3 | 30.1 |
| ReAct | **66.6** | **40.0** |
| IL | 59.9 | 29.1 |
| IL + RL | 62.4 | 28.7 |
| Human Expert | 82.1 | 59.6 |

### 12.4 怎样解释

ReAct 比 Act 的严格成功率高 9.9 个百分点，约等于论文摘要中的 10 个百分点绝对提升。

它的 Thought 能把网页中嘈杂的信息转换成当前决策所需的状态：

```text
颜色符合；尺寸符合；材质尚未确认；不能购买，先查详情。
```

但 ReAct 仍显著低于人类专家。论文观察到，人类更愿意：

- 尝试不同搜索词；
- 浏览多个候选；
- 在没有合适结果时重新表述查询；
- 更细致地核对所有属性。

这说明“会推理”不等于“有成熟的搜索策略”。探索广度、预算分配和停止规则仍是核心问题。

## 13. ReAct-IM 消融：为什么只写子目标还不够

ReAct-IM 是一种更受限制的中间模型。它的思考主要只在宏观层面写当前子目标，缺少完整 ReAct 中随时出现的推理。

结果：

- ReAct-IM 平均成功率 48，最佳 53；
- 完整 ReAct 平均 57，最佳 71。

### 13.1 ReAct-IM 缺少哪些能力

论文案例显示，它可能：

- 没意识到某个子目标是否真正完成；
- 不知道何时切换到下一个子目标；
- 无法根据环境反馈纠正错误理解；
- 缺少“某种操作应在什么位置完成”的常识推理。

例如，它可能在思考中错误地把目标写成“找到一把干净的刀”，拿到普通刀后直接去放置，跳过清洗，随后陷入失败循环。

### 13.2 消融给出的启示

自然语言推理不只是最初写一次计划。对长时程任务而言，还需要：

1. 每一步后的状态估计；
2. 子目标完成检测；
3. 失败归因；
4. 下一子目标选择；
5. 必要时重新规划。

换句话说，Agent 的关键不是“拥有一份计划”，而是**持续维护计划与现实之间的一致性**。

## 14. 可解释性与人类干预

### 14.1 为什么 ReAct 看起来更可解释

人可以直接阅读：

- 模型当前认为目标是什么；
- 它选择某个动作的理由；
- 它从观察中提取了什么；
- 它在哪一步开始偏离。

相比只看到最终答案或动作序列，ReAct 轨迹为调试提供了更丰富的界面。

### 14.2 人类编辑 Thought

论文展示了一个案例：人类只修改轨迹中的两处 Thought，就能改变后续行为并让任务成功。这说明自然语言推理可能成为一种方便的人机协作接口：人不必修改大量模型参数，也不必逐条重写所有动作。

### 14.3 但“可读”不等于“忠实”

必须严格区分：

- **可读性**：这段文字人能看懂；
- **事后合理化**：模型生成一个听起来合理的解释；
- **因果忠实性**：这段文字真的反映了模型产生动作的内部因果机制；
- **可控性**：编辑该文字会稳定地改变行为。

ReAct 主要证明了轨迹具有可读性，并以少量案例展示可编辑性；它没有系统证明 Thought 总是忠实揭示模型内部推理。后续研究若讨论“可解释 Agent”，需要设计干预实验，而不能仅凭自然语言解释看起来合理。

### 14.4 一个可做的忠实性实验

可以固定 Observation，系统替换 Thought：

1. 原始 Thought；
2. 与原始计划相反的 Thought；
3. 无关 Thought；
4. 删除 Thought；
5. 只保留压缩后的状态变量。

比较后续动作分布与任务成功率。如果 Thought 真正参与因果决策，替换它应带来可预测且稳定的行为变化。

## 15. ReAct 与 Agent 各模块的关系

| Agent 模块 | ReAct 中的对应部分 | 覆盖程度 |
|---|---|---|
| 感知 | Observation | 基础覆盖，主要是文本观察 |
| 规划 | Thought 中的目标分解与下一步计划 | 核心贡献之一 |
| 工具使用 | Action 调用搜索或环境接口 | 核心贡献之一 |
| 工作记忆 | 上下文中的历史轨迹和 Thought | 隐式、短期 |
| 长期记忆 | 无独立持久化机制 | 基本未解决 |
| 反思 | 失败后用 Thought 调整 | 初步存在，不是系统化反思模块 |
| 学习 | few-shot 提示与补充微调 | 有限 |
| 多智能体 | 未研究 | 未覆盖 |
| 人机协作 | 人可读、可编辑 Thought 的案例 | 初步探索 |
| 安全控制 | 通过受限动作空间降低风险 | 讨论有限 |

### 15.1 ReAct 是“架构思想”，不是完整 Agent 系统

它解决的是一个关键控制模式：推理与行动怎样交错。但它没有完整解决：

- 长期用户记忆；
- 身份与主体连续性；
- 个性化；
- 多轮关系建模；
- 长期价值对齐；
- 多智能体协商；
- 真实世界权限与安全治理。

因此，对你的实验室方向而言，ReAct 是地基之一，而不是终点。

## 16. 与“人机共生”研究方向的连接

### 16.1 从一次性回答到持续交互

传统问答把人类输入视为一次性问题。ReAct 把任务理解成一个需要持续观察和调整的过程，这更接近真实的人机协作。

### 16.2 自然语言成为控制界面

人类可以阅读甚至修改 Thought，这提示了一种共生接口：

- AI 展示当前目标、依据与不确定性；
- 人类纠正目标或补充约束；
- AI 继续执行；
- 环境反馈共同更新双方认知。

### 16.3 共享态势感知

协作的关键不是 AI 单方面“更聪明”，而是人和 AI 对当前状态形成共同理解。ReAct 的显式轨迹可以作为共享工作区的雏形。

### 16.4 主体性问题

ReAct 中模型表现出目标导向、计划、行动和纠错，因此在行为层面更像一个“主体”。但它不等于证明模型具有心理意义上的主观体验、自我意识或意向性。

研究时应区分：

- **工具性主体性**：系统能围绕目标选择行动；
- **交互性主体性**：系统能在多轮关系中维护立场、承诺和边界；
- **现象意识/主观体验**：哲学与认知科学意义上的意识问题。

ReAct 主要支持第一层，少量触及第二层，不对第三层提供证据。

### 16.5 对多轮人机交互的启发

把用户反馈作为 Observation，可以形成：

```text
AI 提出理解/计划
→ 用户纠正
→ AI 更新状态
→ AI 执行
→ 用户评价结果
→ AI 再规划
```

但真实人机交互还需要处理用户偏好漂移、沟通成本、信任校准、解释粒度和隐私，这些都超出原论文范围。

### 17.1 概念贡献

明确提出并系统验证：自然语言推理与环境行动可以在同一轨迹中协同，而不必分属两个独立系统。

### 17.2 方法贡献

提供简洁通用的 Thought–Action–Observation 提示范式，不需要修改语言模型结构即可应用。

### 17.3 实证贡献

### 17.4 分析贡献

通过错误分析揭示 CoT 和 ReAct 的互补失败模式，并展示组合策略优于单独方法。

### 17.5 人机协作贡献

展示自然语言 Thought 可以成为人类理解和干预智能体行为的接口。

## 18. 局限与批判性阅读

### 18.1 主要模型难以完全复现

核心实验使用 PaLM，外部研究者无法像开源模型那样完整获得相同权重与服务版本。论文补充了 GPT-3 `text-davinci-002` 实验并开源提示与代码，但主要结果仍存在复现门槛。

补充实验中：

- GPT-3 ReAct 在 HotpotQA 上 EM 为 30.8；
- GPT-3 ReAct 在 ALFWorld 上成功率为 78.4；
- 对应的 PaLM 数字约为 29.4 和 70.9。

这说明方法具有一定跨模型可迁移性，但并不等于所有模型和接口版本都会得到相同结果。

### 18.2 提示示例选择敏感

ALFWorld 同时报告平均和最佳提示结果，而且差距不小：ReAct 从平均 57 到最佳 71。说明 few-shot 示例的选择与排列会显著影响结论。

更严格实验应报告：

- 多个随机提示集合；
- 均值和标准差；
- 置信区间；
- 显著性检验；
- prompt selection protocol。

### 18.3 成本比较不完全公平

Standard、CoT、CoT-SC、Act、ReAct 的：

- token 数；
- 模型调用次数；
- 工具调用次数；
- 执行时延；
- 失败重试次数

都不同。只比较准确率无法回答“单位成本下谁更好”。尤其 CoT-SC 需要 21 条采样，ReAct 需要多轮工具交互。

现代评估还应报告：

$$
\text{Cost-adjusted Utility}
= \frac{\text{Task Utility}}{\text{Token Cost} + \lambda\,\text{Tool Cost} + \mu\,\text{Latency}}
$$

这个公式是评价建议，不是原论文公式。

### 18.4 推理轨迹不保证忠实

自然语言 Thought 可能是有效计算步骤，也可能是对已倾向动作的合理化。论文没有提供充分因果证据证明它总能忠实反映内部机制。

### 18.5 检索器较弱

Wikipedia 接口简单，有助于隔离 Agent 行为，但也使结果强烈受搜索质量限制。更强检索器可能提高成绩，也可能降低显式多步搜索的必要性。

### 18.6 缺少长期记忆

ReAct 的“记忆”主要是当前上下文。任务结束后，经验不会自动形成可检索的长期记忆，也没有用户画像、事件记忆、技能记忆或遗忘机制。

### 18.7 循环与终止问题

模型可能重复相同或等价动作。根本原因可能包括：

- 没有明确记录失败动作；
- 状态摘要不完整；
- 缺乏访问集合或循环检测器；
- 终止条件不明确；
- 新观察不足以打破当前策略。

工程上可加入：

- 动作去重；
- 最大步数；
- 状态机约束；
- 失败计数；
- 轨迹压缩；
- 超时回退策略；
- 独立验证器。

### 18.8 数据集标签可能过时

论文给出一个案例：ReAct 从外部页面找到更新后的酒店房间数量，但数据集标签仍是旧信息。按基准答案它“错了”，按现实它可能是对的。

这暴露动态知识任务的评估难题：

- 世界会变化；
- 基准标签被冻结；
- 外部网页可能更新；
- 正确性需要绑定时间戳和证据版本。

### 18.9 真实工具带来安全风险

论文实验中的动作空间是受限的 Wikipedia、WebShop 沙盒和文字环境。真实 Agent 如果连接邮件、支付、代码执行、文件系统或个人数据，就可能：

- 泄露隐私；
- 执行不可逆操作；
- 被网页中的提示注入操纵；
- 因错误推理产生真实损失；
- 越权访问资源。

因此，真实系统还需要权限最小化、沙盒、审批、审计日志、输出校验和可撤销机制。

### 18.10 任务成功不等于人机协作质量

论文主要度量准确率或任务成功率，并未系统测量：

- 用户是否理解系统；
- 用户信任是否校准；
- 解释是否增加认知负担；
- 人类干预是否真正有效；
- 多轮协作是否改善人类决策；
- 不同人群是否得到公平体验。

若研究人机共生，这些是必须补上的评价维度。

## 19. 与 RAG、Plan-and-Execute、Reflection 的关系

### 19.1 ReAct 与 RAG

经典 RAG 常表现为：先检索若干文档，再一次性生成答案。

ReAct 更像**迭代式 RAG**：

```text
根据当前缺口生成查询
→ 获取证据
→ 阅读证据并发现新缺口
→ 再生成查询
→ 综合回答
```

所以 ReAct 的重点不是“有没有检索”，而是“检索决策是否由当前推理动态产生”。

### 19.2 ReAct 与 Plan-and-Execute

Plan-and-Execute 通常先生成较完整的计划，再由执行器逐步完成。

ReAct 通常是局部规划、局部行动、根据观察不断修正。前者强调全局分解，后者强调在线反馈。

二者可以组合：

```text
高层规划器生成子目标
→ 每个子目标内部用 ReAct 执行
→ 失败后回到规划器重规划
```

### 19.3 ReAct 与 Reflection

ReAct 的 Thought 可以处理即时异常，但不一定会在完成整段轨迹后系统总结失败原因。Reflection 类方法通常增加：

- 结果评估；
- 失败归因；
- 经验总结；
- 将总结用于下一次尝试。

可以把它们区分为：

- ReAct：**步内/在线推理—行动闭环**；
- Reflection：**回合后/跨尝试的元认知闭环**。

### 19.4 ReAct 与长期记忆

ReAct 轨迹本身可被存入长期记忆，再在相似任务中检索。但原始方法没有规定：

- 存什么；
- 何时存；
- 如何压缩；
- 如何判断相似；
- 如何处理过期或冲突记忆。

这是从 ReAct 走向持续学习 Agent 的自然研究方向。

## 20. 如何复现一个最小 ReAct Baseline

本节是实验设计蓝图，不要求今天立即动手。

### 20.1 最小系统组件

1. 一个支持文本生成的 LLM；
2. 一个定义清楚的工具集合；
3. 2–6 条 ReAct 示例；
4. 轨迹解析器；
5. 工具执行器；
6. 最大步数与终止条件；
7. 日志和评估脚本。

### 20.2 伪代码

```python
history = [task]

for step in range(max_steps):
    model_output = llm(prompt + history)
    kind, content = parse(model_output)

    if kind == "finish":
        return content

    if kind == "thought":
        history.append(("thought", content))
        continue

    if kind == "action":
        observation = tool.execute(content)
        history.append(("action", content))
        history.append(("observation", observation))

return failure("max steps exceeded")
```

真实实现还必须处理：

- 模型一次同时输出 Thought 与 Action；
- 格式不合法；
- 不存在的工具；
- 参数类型错误；
- 工具超时；
- 内容过长；
- 重复动作；
- 提示注入；
- 最终答案缺少证据。

### 20.3 推荐 baseline 组

为了真正验证 ReAct，而不是只跑一个数字，至少比较：

| Baseline | 目的 |
|---|---|
| Direct | 测试不推理、不工具的下限 |
| CoT | 隔离显式推理的贡献 |
| Tool-only / Act | 隔离外部行动的贡献 |
| ReAct | 联合推理与行动 |
| ReAct without history summary | 测试状态总结作用 |
| ReAct + loop detector | 测试工程防循环机制 |
| ReAct + verifier | 测试独立校验贡献 |

### 20.4 应记录的指标

除任务成功率外，建议记录：

- 平均步骤数；
- LLM 输入/输出 token；
- 工具调用次数；
- 总时延；
- 估算费用；
- 非法动作率；
- 循环率；
- 搜索失败率；
- 有证据支持的答案比例；
- 人工干预次数；
- 干预后成功率。

### 20.5 最重要的消融

删除 Thought 形成 Act baseline。若 ReAct 只比 Act 多写了一些漂亮文字，却没有稳定提高成功率、减少步骤或改善恢复能力，就不能说明 Thought 真正发挥作用。

```text
任务具有多步依赖、信息缺口或环境不确定性

                ↓

                ↓
同时引入检索失败、长轨迹成本、循环、工具安全等新问题
```

## 25. 公式与概念速查表

| 符号/术语 | 含义 | 直观解释 |
|---|---|---|
| $t$ | 时间步 | 当前是第几次交互 |

| EM | Exact Match | 预测答案与标准答案完全一致 |
| Self-Consistency | 多轨迹投票 | 采样多条 CoT 后多数表决 |
| ReAct-IM | 受限中间版本 | 只保留较粗粒度的子目标思考 |

## 26. 常见误解纠正

### 误解 1：ReAct 就是让模型把思维链写出来

不完整。关键是思维链与外部动作、真实观察交替出现，观察能改变后续推理。

### 误解 2：用了搜索就不会幻觉

错误。模型仍可能搜索错误、误读证据、忽略证据，或在最终综合时产生无依据结论。

### 误解 3：ReAct 在所有任务上都超过 CoT

错误。HotpotQA 单独 ReAct 低于 CoT 和 CoT-SC；最好的结果来自组合策略。

### 误解 4：Thought 就是模型真实的内部思维

没有充分证据。它首先是模型生成的自然语言中间文本，是否忠实需要因果实验验证。

### 误解 5：ReAct 已经解决了规划

它提供了在线局部规划能力，但长时程全局规划、计划验证、资源预算和跨任务学习仍未解决。

### 误解 6：轨迹都在上下文里，所以它具有长期记忆

错误。这只是一次会话或任务内的工作记忆，不等于跨任务持久化与可检索的长期记忆。

## 27. 可以继续追问的研究问题

### 27.1 何时应该思考

每步都思考会增加成本；完全不思考又容易犯错。能否学习一个门控策略，只在高不确定性、动作不可逆或状态发生突变时触发 Thought？

### 27.2 思考应该多长

过短不足以表达状态，过长会消耗上下文并可能自我干扰。可以把问题形式化为在任务效用和推理成本之间权衡。

### 27.3 怎样检测循环

能否对动作、目标状态或语义状态做哈希，识别“虽然文本不同但本质重复”的循环？

### 27.4 怎样让人类有效干预

用户应编辑 Thought、目标、约束还是行动候选？不同方式对成功率、信任和认知负担有何影响？

### 27.5 怎样建立长期记忆

成功轨迹、失败轨迹、用户偏好和环境规则应该分别如何存储、检索、更新与遗忘？

### 27.6 怎样验证解释忠实性

对 Thought 做受控干预，观察行动是否按预期改变，并测试不同模型、任务和提示下的稳定性。

### 27.7 怎样安全调用真实工具

对可逆动作与不可逆动作设置不同权限；高风险动作必须请求确认；执行前由验证器检查参数和预期后果。

## 29. 标准化论文卡片

### Problem

语言模型的推理能力与环境交互能力长期被分开研究：前者易幻觉，后者缺少显式规划和状态维护。

### Motivation

人类在完成任务时会交替进行内在语言推理与外部行动，两者互相提供信息和约束。

### Core Idea

将自然语言 Thought 加入模型可输出的动作空间，使 Thought、Action 和 Observation 在同一轨迹中交错。

### Method

使用少量人工轨迹，通过 few-shot prompting 诱导冻结的大语言模型；在知识任务中采用密集推理，在决策任务中采用稀疏推理，并补充小模型轨迹微调实验。

### Experiments

HotpotQA、FEVER、ALFWorld、WebShop；比较 Standard、CoT、CoT-SC、Act、ReAct 及组合方法。

### Main Findings

ReAct 能降低部分事实幻觉、改善交互任务成功率；CoT 与 ReAct 失败模式互补，组合效果最好；高质量 ReAct 轨迹可以用于微调较小模型。

### Strengths

- 方法极简、通用、无需改模型结构；
- 同时覆盖问答和决策；
- 有错误分析与消融；
- 对后来 Agent 框架影响大；
- 轨迹便于调试和人类干预。

### Weaknesses

- 单独 ReAct 并非在所有任务上最佳；
- 主要模型复现受限；
- 成本与统计报告不充分；
- Thought 忠实性未被系统验证；
- 缺少长期记忆和真实安全评估；
- 对提示示例较敏感。

### Takeaway

ReAct 最重要的贡献不是一个固定提示模板，而是把 LLM Agent 明确建模成一个持续闭环：**用语言组织行动，用行动获取证据，再用证据修正语言中的状态与计划。**

## 31. 最终记忆锚点

如果过一个月只记得五件事，请记住：

1. **ReAct = Reasoning + Acting，但本质是反馈闭环，不是标签拼接。**
