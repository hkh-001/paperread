# 当前页面状态提示 单因素配对实验

日期：2026-10-24。方案在新五十题评测启动前保存。

## 问题与唯一改动

旧评测发现：Search 未找到页面后会清空当前页面，但模型仍可能继续 Lookup，收到 `No current page`。旧 dev10 有 2 次，旧 eval50 有 4 次。

本轮只比较是否显式反馈当前页面状态：

- `react_baseline`：保持原消息内容、工具行为及提示词。
- `react_state`：在初始问题、每次真实观察及格式错误提醒后附加 `current_page`，说明 Lookup 只查询当前页，失败的 Search 会清空当前页。

不修改 Search/Lookup 语义，不阻止或代替模型选择动作，不增加步数，不增加纠错调用，不改评分规则，不加入题目专用提示或参考答案。

## 样本与阶段

1. 已知 dev10：两版本各运行十题，用于确认实现和实际运行，不据其表现调提示词或挑选多个版本。
2. 新 eval50_state：从相同作者数据源按 seed=233、offset=60、limit=50 固定选取。按 ID 与题目文本检查，与旧 dev10、旧 eval50 均不重叠。冻结后运行两版本共 100 次作答；软件正常即可执行，不以 dev10 正确率是否上涨作为挑选条件。
3. 旧五十题仅作为问题来源，不再称为独立验证，也不与新题上的成绩直接计算提升。

运行前保存配置、全部题目 ID、执行顺序、代码和提示词哈希；模型只能看到当前问题及工具观察，答案在作答结束后用于评分。

## 控制条件

请求模型沿用 `deepseek-flash`，temperature=0，内置思考关闭；每题最多 7 次模型调用，每次最多 1024 输出 token，观察最多 4000 字符。维基检索间隔 1.5 秒、最多 3 次额外重试、单查询预算 90 秒，沿用七天新鲜期缓存。

每题两版本连续运行，首个版本交替，十题/五十题分别有一半原版先运行、一半状态版先运行。两版本共享同一轮维基响应快照，同一 URL 的重复查询复用相同内容；缓存不含答案。不同路线仍可能访问不同页面，实时资料及模型后端也无法完全固定。缓存与运行顺序影响耗时，因此不将耗时差当成纯方法速度差。

## 预先确定的比较指标

- 主指标：实际执行 Lookup 且返回 `No current page` 的次数。
- 次指标：答案 EM/F1、步数耗尽题数、格式错误、模型调用量及 token 开销。
- 同题比较状态版独对/原版独对的数量，并给出精确 McNemar 检验；小样本结果不作为普遍优越的证明。
- 所有未提交、格式/接口/工具失败均保留记录、按零分计入，不按结果选择性补跑。接口失败时停止排查，不能偷偷替换失败作答。

## 可复跑入口

```bash
python3 -m unittest discover -s tests -v
python3 compare_state_feedback.py --data data/dev10.json --out runs/16-dev10-page-state --phase development
python3 react_lab.py prepare --source data/hotpot_dev_react.json --dest data/eval50_state.json --seed 233 --offset 60 --limit 50
python3 compare_state_feedback.py --data data/eval50_state.json --out runs/17-eval50-page-state --phase evaluation --exclude data/dev10.json data/eval50.json
```

已有输出不应覆盖。仅在代码、数据、配置完全一致时，用原命令加 `--resume` 续跑尚未执行的记录。已存在的失败记录不会被重算。

数据来自此前保存的 ReAct 作者发布的 HotpotQA 简化开发集，采用 HotpotQA CC BY-SA 4.0；来源与哈希见题目元数据。它不是隐藏测试集，也未排除训练污染。
