## 必须单独说明的交互问题

4 道题中，模型一次输出了多步动作和自行编造的 Observation。解析器拒绝了该输出，没有真正执行这些 Search，但 solve() 先把原始输出加入 assistant 历史，格式错误后没有删除它。模型随后可能继续依赖这段未经工具验证的内容。

- `react-dev-02544`、`react-dev-03824`：最终精确答对，但实际工具调用为 0。
- `react-dev-06238`：实际工具调用为 0，输出多个名字；EM=0、F1=0.444。
- `react-dev-03522`：第一次出现上述格式错误，后续又实际执行了 3 次查询并答对。

因此，ReAct 的 6/10 是当前实现的原始得分，不能解释成“六题均由真实检索支持”。其中 2 道正确题没有实际查询工具。这里应把模型的协议遵循问题与实现保留非法输出的问题同时记录。未在本轮中途修复或删去这些记录，以免混合不同版本。

## 值得先读的案例

### 有实际检索证据的成功：react-dev-01551

模型先查询 Geoff LaTulippe，找到电影 Going the Distance；再查询该电影，获得导演 Nanette Burstein，最后提交答案。直接回答错误，CoT 和 ReAct 均正确。这个例子展示了实际的两跳检索链，但不能据此认定检索是模型答对的唯一原因。

### 检索未得到目标信息：react-dev-01557

直接回答与 CoT 均答 duck；ReAct 在 Hardley Flood 页面中未找到目标水鸟信息，之后多次宽泛搜索也没有解决问题，耗尽 7 步未提交。可以观察工具结果与步数预算如何影响结果；仅凭当前页面不能确定缺失信息是网页版本变化还是检索方式造成。

### 工具故障：react-dev-03687

第一次 Search 实际遇到 HTTP 429，重试后仍失败，状态为 tool_error。它反映本轮在线环境的限制，不能把它归类成模型理解错误。该题按预设规则计 0 分。

### 答案范围与精确匹配：react-dev-06238

参考答案只列 Seth MacFarlane，模型输出 Seth MacFarlane、Mike Barker 和 Matt Weitzman，导致 EM=0、F1=0.444。额外名字是否语义上成立尚未独立核验，不能自动改判为正确；它提示我们区分对象错误、答案范围差异和协议错误。此题还存在上述伪造 Observation 问题。

### 首次期刊题再次运行：react-dev-02866

第一次单题运行提交了 1931；本轮在相同提示词与设置下，先查学校，再转到植物园，最后耗尽步数未提交。这说明之前的路径不是代码写死的；也说明 temperature=0 并不能在在线实验中保证完全相同的路径。本轮并未使用事后查到的支持证据。

## 本轮能得出的结论

在这十道调试题和当前实现上，CoT 的答案精确匹配最高。ReAct 增加了模型调用、检索和网络依赖，未在本轮超过 CoT。小样本、不同提示机制、在线页面差异、一次工具限流以及非法输出留在上下文的实现问题，都限制了结果的解释范围。不能由此宣布 ReAct 普遍不如 CoT。

## 下一轮优先级

1. 先修正交互协议：非法多步输出与自行生成的 Observation 不应留作后续已知事实；被拒绝的完整原文仍单独保留作审查证据。
2. 用调试集验证真实工具调用与证据来源，再考虑检索限流和动作格式提示。
3. 若再研究“提交前核验”，与协议修复分开做实验，避免一次修改多个因素。
4. 冻结新设置后，在尚未使用的 eval50 上做独立验证。本轮不继续跑该集合。
